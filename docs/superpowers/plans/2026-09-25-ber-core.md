# ber-core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement ber-core v0.1–v0.2 (plus v0.3 skeleton) as a pure-client Bend library on top of MyLSM, with linear commits, deterministic reads, certified three-way merge and verification.

**Architecture:** Thin overlay over MyLSM: ASCII encoding with prefixes (`object/`, `tree/`, `commit/`, `index/`, `stage/`) + pure Bend cores (key encoding, content hashing, sorted-list merge, tree hash, delta union) + thin `IO` shells for MyLSM effects. No own storage. Per-session staging, materialization only in `create_commit`, interning by content hash for dedupe. Laws in root `LAWS.bend` (human-owned, AI never edits), proofs in root `PROOF.bend` (AI-owned).

**Tech Stack:** Bend 2.0.27 (`bend guide` authoritative), MyLSM pinned by hash (session effects via `src/MyLsmBinding.bend`, the single file that changes if real MyLSM names differ), SHA-256 via `bend-sha256` v0.1.0 pinned at `0xda83506fb9f059ead7afcfa2f498df5f` (machine-checked vs FIPS 180-4; only String→word packing glue is ours), hand-rolled pure sorted-list cores (Laws 1–3 quantify over them; no container lib can discharge our laws), `bend PROOF.bend` as the commit gate, BendHub by hash.

**Naming:** No `ber_` prefix anywhere. All identifiers verbose English: `session_identifier`, `namespace_name`, `record_identifier`, `commit_identifier`, `parent_commit_identifiers`, `stored_value`, `merged_entries`.

**Supersession (mylsm v0.2.0 pinned):** sketches below showing a threaded `session_handle` are outdated — MyLSM is a `Sess` state monad (Task 0 binding), not handle-threading. Read `session_handle` params as "compose in the ambient `Sess` do-block" and `session_put(handle, k, v)` as `store_value(k, v)`. The worker adapts every sketch to the Task-0 binding; the binding is authoritative.

**Bend rules that bind every task (from `bend guide` + `AGENTS.md`):**
- `import Base` + `import ./path.bend as Alias`. No `from x import y`.
- `type Name is Data:` with `Constructor{fields}`; `def name(arg: Type) -> Ret:` with body; `match param:` with `case`; no `if`, no `for` (match on `True{}`/`False{}`, recursion with a structurally smaller argument first, fuel `Nat` for outer loops).
- Affine by default: thread handles, mark reusable inputs with `+`, erased sizes with `-`.
- `match` only on parameters or pattern-bound variables — computed values go through a helper def.
- Parallelize independent balanced calls with parallel `let` (`left_result right_result = f(a) g(b)`); GPU via call-site `!`. I/O stays sequential.
- Laws state properties of **pure cores**, never of `IO` actions. Every task ends with `bend PROOF.bend` green before `git commit`.

**Spec:** `docs/superpowers/specs/2026-09-25-ber-core-design.md`

## Approaches considered

- **A. Thin overlay with pure cores + IO shells (recommended):** encoding + pure logic, staging in `stage/`, trees/indexes materialized only on commit. Laws quantify over pure cores so Bend can prove them. Pro: inherits MyLSM durability, provable, testable. Contra: requires MyLSM prefix scan (`index/{namespace}/{record}/`).
- **B. Fully materialized trees per commit:** O(1) reads but O(n) writes per commit — rejected.
- **C. Lazy deltas only:** cheap commits but reads walk full history O(history), Law 1 unprovable in practice — rejected.

Decision: A. If prefix scan proves expensive, optimize in v0.3 via `children_hashes` partitioning, no API change.

```python
# upstream (bend-sha256 v0.1.0). Verify once locally with THEIR gate before trusting:
#   bend <their-bundle>/PROOF.bend   (they checked on Bend 2.0.16; we run 2.0.27)
# TRUSTED (do not re-prove): ProvenSha256.sha256/hex (FIPS 180-4 machine-checked),

# OWNED (unproved glue, keep tiny): group_bytes_big_endian (byte list -> U32 words).
# Covered by differential test vs python hashlib, incl. 55/56/64-byte boundaries
# and multi-byte UTF-8 payloads.
def compute_sha256_hex(input_text: String) -> String:
  match Utf8Lib.encode(input_text):
    case Fail{encode_error}:
      "INVALID_UTF8_INPUT"
    case Done{raw_bytes}:
      packed_words : Array<U32> = group_bytes_big_endian(raw_bytes)
      # CORRECTNESS TRAP: the length argument is BYTE count, not String.length.
      # For multi-byte payloads they differ; using char count silently hashes
      # a truncated message. Byte count comes from the encoded list itself.
      byte_count : Nat = List.length(&2, U32, raw_bytes)
      match ProvenSha256.sha256(packed_words, byte_count):
        case None{}:
          "INVALID_HASH_INPUT"
        case Some{digest_words}:
          ProvenSha256.hex(digest_words)
```
